Bước 1 / 6
Tạo Custom App trên Lark Developer

Mỗi doanh nghiệp dùng một ứng dụng riêng để HiLark hoạt động độc lập trong tenant của bạn.

Console https://open.larksuite.com/app Mở ↗
  1. Đăng nhập bằng tài khoản Admin hoặc tài khoản có quyền phát triển ứng dụng của doanh nghiệp.
  2. Nhấn Create custom app (Tạo ứng dụng tùy chỉnh).
  3. Đặt tên là HiLark, nhập mô tả ngắn và chọn biểu tượng bất kỳ.
  4. Nhấn Create để vào trang quản lý ứng dụng.
Nếu doanh nghiệp dùng Feishu (Trung Quốc), truy cập open.feishu.cn/app thay cho địa chỉ trên.
Bước 2 / 6
Bật tính năng Bot

HiLark cần năng lực Bot để nhận tin nhắn, gửi thẻ duyệt và chào Admin sau khi cài đặt.

  1. Trong menu bên trái, chọn Add features (Thêm tính năng).
  2. Tại thẻ Bot, nhấn Add.
  3. Vào Bot trong menu trái, bật các tùy chọn cho phép Bot nhận tin nhắn nhóm và tin nhắn riêng (DM).
Bật Bot sẽ tự động kích hoạt sự kiện card.action.trigger dùng cho thẻ duyệt bản nháp / duyệt tri thức.
Bước 3 / 6
Lấy 4 khóa & Kết nối với HiLark

Lấy App ID, App Secret, Verification Token và Encrypt Key từ Lark để HiLark xác thực và sẵn sàng giải mã webhook.

  1. Vào Credentials & Basic Info ở menu bên trái: sao chép App ID (bắt đầu bằng cli_) và App Secret.
  2. Vào Events & Callbacks → tab Encryption Strategy: sao chép Verification Token và Encrypt Key (nhấn Generate nếu đang để trống).
  3. Nhập 4 khóa vào bảng bên dưới và nhấn Xác thực & Lưu khóa vào HiLark.
💡 Tại sao cần lưu khóa trước? Khi cấu hình Request URL ở bước tiếp theo, Lark sẽ gửi gói tin kiểm tra challenge mã hóa bằng Encrypt Key. HiLark cần biết Encrypt Key trước để giải mã thành công ngay lập tức.
✔ Đã kết nối App thành công! HiLark đã lưu Encrypt Key và sẵn sàng tiếp nhận & giải mã sự kiện. Hãy nhấn Tiếp theo → để cấu hình quyền và sự kiện.
Bước 4 / 6
Thêm quyền (Scopes)

Cần cấp hai nhóm quyền: tenant (Bot gọi API) và user (hành động dưới danh nghĩa người dùng).

  1. Vào Permissions & Scopes (Quyền & phạm vi).
  2. Nhấn Batch import/export scopes (Nhập/xuất hàng loạt).
  3. Dán nguyên khối JSON bên dưới → Next → Add scopes.
Tenant
User
Quyền offline_access (user) là bắt buộc để HiLark nhận refresh token. Thiếu quyền này, phiên OAuth sẽ hết hạn và Bot không tự gia hạn được.
Bước 5 / 6
Cấu hình Request URL & Đăng ký sự kiện

HiLark nhận tin nhắn, thẻ tương tác và thay đổi dữ liệu qua Event Subscriptions.

✔ Sẵn sàng xác thực: Do bạn đã lưu Encrypt Key vào HiLark ở Bước 3, khi bạn dán Request URL và nhấn Save, HiLark sẽ tự động giải mã và phản hồi challenge thành công ngay lập tức!
  1. Tab Event configuration → chọn phương thức Send notifications to developer's server và dán Request URL bên dưới → Nhấn Save.
  2. Nhấn Add Events, tìm và thêm từng sự kiện trong danh sách (sao chép mã nhanh bằng nút bên cạnh).
  3. Tab Callback configuration: chọn cùng phương thức và dán cùng Request URL, thêm card.action.trigger.
Request URL
Mỗi sự kiện cần có quyền đi kèm — bạn đã import ở Bước 4. Sự kiện app_ticket chỉ dành cho ISV/Store App, không cần với Custom App.
Bước 6 / 6
Khai báo Redirect URL & phát hành

OAuth user cần Redirect URL hợp lệ, và ứng dụng phải được phát hành thì quyền mới có hiệu lực.

  1. Vào Security Settings (Cài đặt bảo mật) → mục Redirect URLs → thêm địa chỉ bên dưới.
  2. Vào Version Management & Release → Create a version, điền số phiên bản (vd. 1.0.0) và ghi chú cập nhật.
  3. Nhấn Save → Publish. Với doanh nghiệp của bạn, Admin có thể tự duyệt trong Lark Admin Console.
  4. Sau mỗi lần thêm/sửa scope hoặc event, cần tạo phiên bản mới và phát hành lại.
